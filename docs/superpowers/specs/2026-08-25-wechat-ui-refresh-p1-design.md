# P1-A：PC 微信视频号页面自动刷新设计

## 目标

在用户已经于 PC 微信内部打开任意一个视频号页面的前提下，启动采集任务后自动完成页面刷新。用户不再需要在代理和 ltaoo 启动后手动按 F5；系统随后继续执行既有的 profile 就绪等待、三链接批处理、评论/回复分页、幂等入库和安全清理。

本阶段只解决“刷新已打开页面”，不负责搜索关键词、输入分享链接或选择搜索结果。

## 已知基础

- ltaoo 和 Mihomo 由 TrendRadar 运行时统一启动和清理。
- ltaoo 状态就绪后，批处理使用共享 60 秒 profile 就绪窗口。
- 当前运行时已能通过 Win32 `PostMessage` 向可见 PC 微信窗口发送 F5。
- 视频号页面通常由 `WeChatAppEx` WebView 承载，`Weixin` 是宿主进程。
- 当前真实验收已证明自动刷新后的三链接采集、评论/回复入库和清理回执链路可运行；P1 重点是把窗口选择、激活和失败诊断固定下来。

## 时序

```text
预检
  -> 安装临时 CA / 配置临时路由
  -> 启动 ltaoo 和代理
  -> 等待 ltaoo runtime status=ready
  -> 枚举 PC 微信窗口
  -> 选择视频号 WebView
  -> 激活窗口并发送一次 F5
  -> 等待共享 60 秒 profile 就绪
  -> 执行三链接批处理
  -> 校验评论/回复分页和幂等入库
  -> 逆序清理并写 cleanup receipt
```

刷新必须发生在 ltaoo 就绪之后、批处理请求之前。刷新成功不等于 profile 已就绪，后续仍必须经过现有 60 秒共享等待。

## 窗口选择策略

只考虑进程名 `Weixin`、`WeChat` 和 `WeChatAppEx`，并要求主窗口句柄有效、窗口可见且标题非空。

选择顺序固定为：

1. 当前前台窗口是唯一候选时，选择前台窗口；
2. 否则，存在唯一可见的 `WeChatAppEx` 时，选择该 WebView 页面窗口；
3. 否则，存在唯一可见的 `Weixin` 宿主窗口时，选择该窗口；
4. 仍无法唯一确定时，返回 `wechat_window_ambiguous`。

选择后只向目标窗口发送一次 F5。不得向所有候选窗口广播按键，也不得把普通浏览器窗口作为候选。

## 安全边界

P1-A 不使用剪贴板，不输入 URL 或关键词，不读取页面文本，不点击搜索结果，不注入额外脚本。窗口操作仅限于：确认候选窗口、尝试激活目标窗口、发送一次 F5。

如果窗口不存在、窗口不唯一、激活失败或 F5 发送失败，运行时必须进入既有清理流程，并输出封闭错误码；不得继续提交批处理请求。

## 错误分类

| 错误码 | 阶段 | 用户可见含义 |
|---|---|---|
| `wechat_window_not_found` | startup | 未找到可用的 PC 微信视频号窗口 |
| `wechat_window_ambiguous` | startup | 找到多个无法安全区分的窗口 |
| `wechat_page_refresh_failed` | startup | 页面刷新动作发送失败 |
| `profile_not_ready` | detail | 刷新后 60 秒内仍未建立页面桥 |

以上错误必须保留 CA、路由、ltaoo 进程和端口的安全清理回执。

## 可行性验证矩阵

### 静态和单元验证

- PowerShell 语法解析通过；
- 运行时脚本测试确认只允许受控进程名和 Win32 消息；
- 测试拒绝 `SendKeys`、剪贴板、普通浏览器 URL 和任意命令执行；
- 窗口选择测试覆盖前台窗口、唯一 WebView、唯一宿主和歧义窗口；
- TrendRadar 测试确认刷新参数只在微信视频号采集命令中出现。

### 受控真实验证

每轮使用同一授权、同一 PC 微信账号和同一组三个分享链接，记录运行 ID、窗口选择结果、profile 状态、作品/评论/回复计数和 cleanup receipt，不记录 Cookie、响应正文或秘密。

必须完成以下场景：

1. 一个可见 `WeChatAppEx` 页面窗口：自动刷新后 profile 就绪；
2. `Weixin` 与 `WeChatAppEx` 同时存在：选择 WebView，不误刷新宿主；
3. 页面窗口不存在：返回 `wechat_window_not_found` 并安全清理；
4. 多个同类页面窗口：返回 `wechat_window_ambiguous` 并安全清理；
5. 连续至少三轮真实任务：三链接处理、评论/回复分页和清理结果稳定；
6. 同一配置复跑：作品不重复、`comment_id` 不重复、历史数据保留。

## 验收标准

P1-A 可交付需要同时满足：

- 用户无需在运行时启动后手动按 F5；
- 自动刷新发生在 ltaoo 就绪之后；
- profile 就绪等待仍为共享 60 秒；
- 真实三链接任务至少一轮达到 3/3 作品处理；
- 连续复跑无重复 `comment_id`；
- 所有失败路径都有安全清理回执；
- 未实现搜索、输入和结果选择，不对 P1-B/P1-C 做承诺。

## 非目标和后续

- P1-B：已知分享链接的 UI 自动导航；
- P1-C：关键词搜索并选择视频；
- 这些能力需要单独验证 UI Automation 树、控件稳定性、登录状态和人工验证行为，不纳入 P1-A 的交付判断。
