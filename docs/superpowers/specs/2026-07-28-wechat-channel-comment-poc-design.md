## 1. 目标

本 POC 验证通用品牌舆情监控系统能否复用隔离虚拟机快照中的 PC 微信登录状态，采集微信视频号公开搜索结果及公开评论。首次登录必须在隔离虚拟机内由操作员完成，不复制宿主机微信登录数据。

单次真实验证必须完成以下任务：

1. 搜索品牌关键词“青云装饰”。
2. 按微信接口的原始顺序获取最多前 10 个公开作品；若搜索明确耗尽，则处理全部有效作品。作品包含视频、图文及其他非视频作品。
3. 对每个作品最多采集 100 条一级评论。
4. 对入选一级评论最多采集合计 200 条二级回复。
5. 输出作品、评论、脱敏证据和字段验证报告；原始响应默认只在内存中参与解析与哈希。
6. 验证评论 ID、父评论 ID、正文、公开账号、时间、IP 属地、内容媒体类型、作品媒体类型和作品定位字段。
7. 在登录、扫码、真人验证或页面上下文匹配需要人工介入时进入有时限的人工处理状态，不绕过验证码。
8. 只执行公开数据的只读采集。

## 2. 非目标

- 不实现点赞、评论、回复、发布、收藏、关注、转发或删除等写操作。
- 不下载作品媒体文件。
- 不修改 TrendRadar，也不在本阶段接入统一作品或评论模型。
- 不把 POC 扩展为长期无人值守采集服务。
- 不绕过登录、访问控制、验证码、真人验证或微信的速率限制。
- 不运行仓库提交的 `wx_channel.exe`、`wx_channel_cloud.exe` 或 `wx_channel_radar.exe`。
- 不在宿主机安装测试证书或网络驱动。
- 不从宿主机复制微信 Cookie、登录数据库、密钥或其他登录状态到隔离虚拟机。

## 3. 已审查的上游能力与风险

### 3.1 可复用能力

当前提交已经具备以下只读链路：

- `internal/api/search.go` 通过 `finderSearch` 的 Type=3 场景搜索作品。
- `internal/assets/inject/api_client.js` 将页面内微信 API 桥接到本地 WebSocket。
- `finderGetCommentList` 支持一级评论分页和按根评论获取回复分页。
- `internal/api/search.go` 已实现评论分页、评论 ID 去重和二级回复遍历。
- `internal/api/comment_export_persist.go` 已实现原子写入和中间检查点。

本 POC 不复用上游完整应用启动链，只复用经过裁剪和加固的搜索、详情、评论分页及 WebSocket 协议能力。

### 3.2 阻止直接运行的风险

当前源码不能按默认入口直接用于真实验证：

- `pkg/sunnynet/SunnyNet/SunnyNet.go` 的包初始化会调用网络参数调整逻辑。
- `pkg/sunnynet/src/CrossCompiled/windows.go` 会通过 `netsh` 修改 Windows IPv4 和 IPv6 动态端口范围。
- `internal/app/app.go` 会自动检查并安装 SunnyNet 根证书。
- SunnyNet 代理、WebSocket/API 服务和指标服务默认监听 `0.0.0.0` 或所有网卡。
- Windows 启动链会加载网络驱动并代理 `WeChatAppEx.exe`。
- `internal/config/config.go` 默认启用云连接和指标服务，并在默认值初始化时生成机器 ID。
- `internal/config/device_id.go` 能采集并持久化 MAC、CPU、主板、磁盘序列号和主机名。
- 应用启动时会访问 GitHub 检查更新，并可能连接上游默认云 Hub。
- `api_client.js` 会把完整搜索和评论响应写入浏览器控制台。
- 仓库跟踪了 `internal/assets/certs/SunnyRoot.key`，SunnyNet 源码中还包含同一类静态根证书私钥。
- 当前 `.gitignore` 未完整覆盖 POC 证书、令牌、运行目录、证据和规范化结果。

公开在 Git 历史中的上游私钥不再被视为秘密，但绝不能成为受信任的 POC CA，也不能进入 POC 构建产物的运行路径。

## 4. 方案选择

### 4.1 安全审查后的决策变更

早期约束是“先验证、暂不改源码”，其前提是能够在不触发额外系统和网络副作用的情况下直接复用上游只读能力。第 3 节的源码审查证明该前提不成立：默认入口会修改网络参数、安装 CA、初始化硬件指纹、开放监听并连接外部服务。直接运行或只用脚本包装无法满足本 POC 的安全边界。

因此，原决策在安全审查后明确变更为“先增加受限 POC 模式，再进行验证”。该变更只授权实现本规格定义的最小只读入口和安全控制，不授权修改 TrendRadar、增加微信写操作或扩大长期采集范围。此前对该路线的确认是对安全审查结果的响应，不应被解释为无边界的源码改造授权。

### 4.2 仓库关系与开发前置条件

当前目录是上游仓库的本地克隆，不是 fork。文档编写时 `origin` 仍指向 `https://github.com/nobiyou/wx_channel.git`。

在修改任何程序源码前必须：

1. 在用户控制的 GitHub 命名空间创建该仓库的 fork。
2. 将原作者仓库配置为 `upstream`，将用户控制的 fork 配置为 `origin`。
3. 获取并核对 `upstream` 的基线提交仍为 `11d49cee1da9032230dc5c0eece79bcf03da3e82`。
4. 只在 `codex/...` 功能分支开发，不直接在本地 `main` 上修改源码。

### 4.3 选定方案

采用“在当前本地克隆及后续 fork 中增加受限 POC 模式”的方案。

不采用以下方案：

- 仅用脚本包装现有程序：无法阻止包初始化、静态证书、全网卡监听和硬件指纹等源码级副作用。
- 立即重写独立采集器：边界最干净，但会显著增加首版工作量和破坏现有微信页面桥接的风险。

POC 成功后，可以把最小代理和采集链进一步抽取为独立组件。

## 5. 架构

POC 使用独立源码入口，构建产物固定命名为 `wx_channel_poc.exe`。该入口不得调用现有 `app.Run()`。

### 5.1 生命周期控制器

职责：

- 执行隔离环境、安全配置、端口、证书、驱动和目录预检。
- 生成本次运行的任务 ID、随机本地令牌和独立 CA。
- 在显式人工确认后加载驱动、信任证书并启动代理。
- 管理 `waiting_for_human`、`waiting_for_target_context`、人工等待延长、运行、停止和清理状态。
- 执行幂等清理并生成不含敏感数据的清理回执。

启动必须要求显式的隔离环境确认；缺少确认时拒绝运行。该确认不能替代真实环境隔离，真实验证仍只能在可回滚或可销毁的 Windows 虚拟机中进行。

### 5.2 最小代理桥

职责：

- 移除 SunnyNet 包初始化时的 `netsh` 副作用。
- 只在 `127.0.0.1` 上监听代理端口。
- 只加载与 `WeChatAppEx.exe` 精确匹配的进程代理规则。
- 使用本次任务生成的 CA 解密目标页面 HTTPS 流量。
- 只对受支持的视频号页面注入 POC JavaScript。

禁止全进程代理和 Windows 系统代理。驱动安装及加载只允许发生在隔离虚拟机中。

### 5.3 最小页面桥

页面桥只提供以下能力：

- `finderSearch`
- `finderGetCommentDetail`
- `finderGetCommentList`
- 页面能力和可见性心跳

页面桥不得包含或调用下载、点赞、评论、回复、发布、收藏、关注、转发、云命令或自动刷新逻辑。它不得在浏览器控制台打印请求体、响应体、账号、评论正文或令牌。

### 5.4 采集编排器

职责：

- 搜索固定关键词。
- 规范化搜索结果结构变体。
- 按原始顺序分页和去重，选择最多前 10 个作品；搜索明确耗尽时选择全部有效作品。
- 逐作品串行采集详情、一级评论和二级回复。
- 执行数量上限、请求节流、检查点和恢复。
- 将微信源字段映射到稳定的 POC JSON 模型。

### 5.5 结果写入器

职责：

- 原子写入规范化数据、验证报告、脱敏证据、清单和检查点。
- 在内存中解析原始响应并计算原始响应 SHA-256；完成映射后尽快释放原始响应缓冲区。
- 在任何证据落盘前执行敏感字段、令牌模式和带查询参数 URL 扫描；未经扫描的响应不得直接或间接落盘。
- 确保普通输出中不存在 Cookie、Authorization、会话令牌、证书私钥、完整请求头、查询令牌或未经脱敏的 URL。

## 6. 运行目录与 Git 隔离

实施阶段在写入任何运行数据前，必须将以下目录加入 `.gitignore`：

- `.poc-build/`
- `.poc-secrets/`
- `.poc-data/`
- `.poc-runtime/`
- `var/`

同时忽略本地证书私钥、临时令牌、Cookie 导出、登录状态、配置覆盖、可选加密原始证据、规范化结果、检查点和运行日志的通用命名模式。

POC 启动时必须使用 `git check-ignore` 确认任务目录确实被忽略；未被忽略时拒绝创建敏感文件。

上游已跟踪的 `SunnyRoot.key` 从 POC 工作树的运行路径移除。无需重写上游 Git 历史，但 POC 构建必须通过扫描证明没有嵌入静态 RSA 私钥。

## 7. 数据流

### 7.1 启动前预检

首次环境准备必须发生在 POC 进程启动之前：操作员在隔离虚拟机中安装并登录 PC 微信，确认视频号可访问，然后在尚未安装 POC CA、加载驱动或启动代理的状态下创建登录基线快照。完成该快照后，才能启动 POC 并执行以下预检。

预检项目：

- 当前基线提交和本地差异可记录。
- 运行者已确认隔离 Windows 环境。
- 隔离虚拟机已在其中完成 PC 微信人工登录，并已创建“登录完成、POC 系统变更前”的可回滚快照。
- 未从宿主机复制微信 Cookie、登录数据库、密钥或其他登录状态。
- 仓库预编译 exe 未被选择为执行目标。
- POC 运行目录被 Git 忽略且仅当前用户可访问。
- 代理、API 和 WebSocket 端口可用。
- 上游公开 SunnyNet 根证书未被信任。
- POC 将只绑定回环地址。
- 云、同步、雷达、指标、更新、下载、硬件指纹和管理组件不会初始化。
- 当前没有冲突的 SunnyNet 驱动或代理实例。

任一安全预检失败都必须停止任务。

### 7.2 运行准备

1. 生成任务 ID。
2. 在 `.poc-secrets/<job_id>/` 中生成独立 CA 和私钥。
3. 生成只存在于内存或受限秘密文件中的随机本地令牌。
4. 向操作员显示不敏感的 CA 指纹和变更摘要。
5. 经人工确认后，只把本次 CA 安装到隔离虚拟机当前用户的受信任根证书库。
6. 启动回环代理和 API/WebSocket 服务。
7. 加载只匹配 `WeChatAppEx.exe` 的驱动规则。

### 7.3 微信页面就绪

每次 POC 运行从第 7.1 节定义的登录基线快照启动或恢复，只复用该快照中的登录状态，不复制或挂载宿主机微信登录数据。

若快照中的会话失效，或页面要求登录、扫码或真人验证，状态变为 `waiting_for_human`，并按第 11.2 节启动 300 秒人工等待计时。系统不识别、不填写、不提交、不绕过验证码。

页面桥报告同时支持搜索、详情和评论方法后，任务进入搜索阶段。

### 7.4 搜索和作品选择

- 关键词固定为“青云装饰”。
- 使用 `finderSearch` 的作品搜索场景。
- 按响应中的原始顺序处理分页。
- 按作品 ID 去重，保留第一次出现的位置。
- 缺少作品 ID 的搜索项不具备评论定位能力，不计入前 10 个有效作品；保留其响应 SHA-256 和脱敏结构证据，在验证报告中标记结构异常，然后继续分页寻找有效作品。
- 视频、图文及其他公开作品均可入选。
- 取得 10 个作品后立即停止搜索分页。
- 只有响应中经上游源码、已审查 fixture 或真实响应验证为“没有下一页”语义的结束字段明确触发时，才能认定搜索耗尽；不得仅因某一页为空、游标缺失或本地超时推断耗尽。
- 搜索明确耗尽而不足 10 个时，仍采集全部实际有效作品的评论；这只把 `coverage_status` 记为 `source_exhausted_below_target`，不得单独据此把采集能力判为不可行或不确定。
- 因超时、错误或人工取消而停止搜索，且既未取得 10 个作品也未确认耗尽时，`coverage_status` 记为 `incomplete`。

### 7.5 评论采集

每个作品串行处理，任意时刻只能存在一个微信 API 请求。相邻请求的开始时间至少间隔 1 秒。

一级评论：

- 使用作品 ID 和 nonce ID 调用 `finderGetCommentList`。
- 按 `lastBuffer` 分页。
- 按评论 ID 去重并保持第一次出现的顺序。
- 缺少评论 ID 的源记录以 `evidence_ref + source.ordinal` 保留一次，不生成替代 ID，也不参与跨页 ID 去重；若该一级评论报告存在回复，由于无法安全定位回复分页，该作品标记为 `partial`。
- 最多保留 100 条；达到上限后停止该作品的一级分页。

二级回复：

- 按已选一级评论的顺序处理。
- 合并一级响应内嵌回复和以根评论 ID 请求的独立回复分页。
- 按回复评论 ID 去重并保持第一次出现的顺序。
- 每个作品最多保留合计 200 条；达到上限后停止后续回复分页。

达到上限不是错误。作品结果必须记录是否截断、触发的上限以及微信是否仍报告存在更多数据。

### 7.6 页面上下文不匹配

首先直接使用搜索结果中的作品 ID 和 nonce ID 请求评论。若微信返回页面上下文不匹配，任务变为 `waiting_for_target_context`，向操作员显示作品序号和非敏感操作提示，并按第 11.2 节等待操作员在视频号中打开该作品。

首版不使用模拟点击、键盘注入或其他 UI 自动化切换作品。页面能力心跳确认上下文就绪后，编排器重试当前只读请求。

### 7.7 检查点与恢复

以下时点必须原子保存检查点：

- 搜索作品集合确定后。
- 每个一级评论分页完成后。
- 每个二级回复分页完成后。
- 每个作品完成或失败后。
- 人工等待超时、操作员取消或任务进入清理前。

恢复时从最后一个完整分页继续。已写入的作品和评论以源 ID 去重，不生成替代 ID。检查点不得包含 Cookie、请求头、本地令牌或 CA 私钥。

## 8. 输出结构

每个任务目录包含：

- `dataset.json`：规范化作品和评论。
- `validation.json`：字段出现率、缺失率、格式错误、能力结论和覆盖结论。
- `manifest.json`：运行状态、能力状态、覆盖状态、数量、限制、截断、文件哈希和构建来源。
- `evidence/*.json`：按请求序号保存的脱敏证据摘要。
- `checkpoint.json`：可恢复状态。
- `cleanup-receipt.json`：不含敏感数据的清理结果。

证据文件名只使用任务内请求序号，不包含关键词、作品 ID、账号或评论 ID。

默认脱敏证据只包含请求序号、只读方法类别、原始响应 SHA-256、响应字节数、字段名、JSON 类型、数组或记录数量、脱敏规则版本及各类脱敏命中数量；不包含原始字段值、完整 URL 或传输请求头。`source.evidence_ref` 指向该脱敏摘要，`source.ordinal` 指向响应内的逻辑记录顺序。

“原始响应”指页面桥收到的微信页面 API 响应载荷字节，不包含 HTTP/WebSocket 请求头、Cookie、Authorization、本地控制令牌或证书材料。原始响应只能在内存中完成以下处理：计算 SHA-256、敏感扫描、解析、规范化映射和脱敏摘要生成。哈希必须在解析或脱敏改写前计算；本地桥接器添加的传输封装不计入该哈希。

默认禁止原始响应落盘。只有在结构漂移无法仅凭脱敏摘要诊断时，操作员才可对本次任务显式批准临时保留；批准不能设为默认值，也不能沿用到后续任务。即使获批，也必须先在内存中完成敏感扫描，再使用带完整性校验的加密方式从内存直接写入 `.poc-secrets/<job_id>/raw-evidence/*.enc`，不得创建明文临时文件。加密密钥与密文分开保存且不进入日志、Git、聊天或普通结果目录。加密原始证据必须在验收完成或任务终止后的清理阶段立即删除，不适用 7 天保留期。

```json
    "limits": {
      "works": 10,
      "top_level_comments_per_work": 100,
      "replies_per_work": 200
    }
  },
  "works": [],
  "comments": []
}
```

示例值仅用于说明结构，不得被测试或实现当作真实采集数据。

`job.status` 只表示运行完成度，只能取 `completed`、`requires_human`、`partial` 或 `failed`。`job.capability_status` 只能取 `verified`、`verified_with_gaps`、`inconclusive` 或 `failed`。`job.coverage_status` 只能取 `target_met`、`source_exhausted_below_target` 或 `incomplete`。运行中的生命周期状态由检查点单独记录，不写成最终结论。

### 8.2 作品模型

每个作品包含：

- `work_id`
- `object_nonce_id`
- `title`
- `author.account_id`
- `author.display_name`
- `media_type.raw_code`
- `media_type.normalized`：`video`、`image_text`、`live`、`other` 或 `unknown`
- `locator.keyword`
- `locator.search_rank`：全局 1 到 10
- `locator.search_page`
- `locator.index_in_page`
- `locator.public_url`
- `collection_status`：`completed`、`partial`、`no_comments` 或 `failed`
- `top_level_comment_count`
- `reply_count`
- `truncation.truncated`
- `truncation.reasons`
- `source.evidence_ref`

`work_id` 和 `locator.search_rank` 是完成作品定位验证的必备字段。其他源字段缺失时使用 `null`。

媒体类型规范化只允许使用已经由微信响应字段或已验证夹具证明的映射。无法证明含义的原始代码必须映射为 `unknown`，不得根据标题、正文或 DOM 外观推断。

### 8.3 评论模型

每条评论包含：

- `comment_id`
- `work_id`
- `level`：`1` 或 `2`
- `parent_comment_id`
- `root_comment_id`
- `retrieval_root_comment_id`
- `content.text`
- `content.media_type.raw_code`
- `content.media_type.normalized`
- `account.account_id`
- `account.display_name`
- `account.avatar_url`
- `created_at.raw`
- `created_at.unix_seconds`
- `created_at.iso_8601`
- `ip_location.label`
- `source.method`
- `source.evidence_ref`
- `source.ordinal`

`parent_comment_id` 和 `root_comment_id` 只保存微信源响应明确提供的值。一级评论中的 `"0"` 可规范化为 `null`，并保留对应的脱敏证据引用和原始响应哈希。源响应未提供父 ID 时不得推断。

微信源响应缺少 `comment_id` 时仍输出该记录并将字段设为 `null`，使用 `source.evidence_ref` 和 `source.ordinal` 定位证据，但不得把二者拼接成评论 ID。

`retrieval_root_comment_id` 记录请求回复分页时使用的一级评论上下文。它是采集上下文，不冒充微信源字段。

时间同时保留原始值、可解析的 Unix 秒和 UTC ISO 8601。解析失败时保留原始值，规范化值为 `null`。

IP 属地只保存公开文本，不保存、推导或解析真实 IP 地址。

### 8.4 缺失字段语义

字段验证状态只有以下五类：

- `present`
- `missing_in_source`
- `invalid_format`
- `not_applicable`
- `redacted_for_safety`

不得使用空字符串、零值或推断值掩盖源数据缺失。一级评论的父评论 ID 为 `null` 属于 `not_applicable`。正文为空但源媒体类型表明是图片、表情或其他非文本内容时，不判定为采集失败。源字段存在但因秘密扫描而不能安全输出时，值设为 `null` 并标记 `redacted_for_safety`，不能伪装成 `missing_in_source`。`redacted_for_safety` 不能计作该字段类别已被安全观察；若待验证字段类别没有其他安全样本，`capability_status` 只能为 `inconclusive`。

`validation.json` 汇总字段出现率和错误，不复制评论正文。报告可以使用作品排名和任务内评论序号定位问题。

## 9. 日志和敏感数据

日志只允许包含：

- 任务状态和阶段。
- 请求序号、方法类别、耗时、响应字节数和错误类别。
- 作品排名、累计数量和是否截断。
- 不含目标数据的安全检查结果。

日志禁止包含：

- Cookie、Authorization、完整请求头或查询令牌。
- 本地控制令牌、CA 私钥或私钥路径内容。
- 评论正文、账号 ID、昵称、头像 URL、作品 ID、nonce ID 或原始响应。
- 页面完整 URL；状态中只允许记录规范化页面路径。

浏览器控制台遵循相同限制。

所有普通输出文件在原子替换目标文件前必须通过同一套秘密扫描。`locator.public_url`、`account.avatar_url` 及未来新增的 URL 字段一律移除查询参数和片段，并在验证报告中记录脱敏规则但不记录被移除内容；移除后仍命中高置信秘密模式或无法形成安全 URL 时，字段输出 `null` 并标记 `redacted_for_safety`。任何其他字段命中高置信 Cookie、令牌、私钥或认证材料模式时同样拒绝原值落盘。扫描器未能阻止敏感值进入普通输出属于安全失败；扫描命中被安全移除时按第 8.4 节判断能力状态。

## 10. 本地接口与网络边界

- 代理、HTTP API 和 WebSocket 只监听 `127.0.0.1`。
- 本地接口每次运行使用新的随机令牌。
- 令牌通过请求头传递，不允许通过 URL 查询参数传递。
- 只注册状态、搜索、详情、评论和任务控制相关的最小路由。
- 不注册证书安装、代理重启、设置修改、文件、下载、上传、队列、雷达或云命令路由。
- POC 进程不得主动访问更新、指标、云 Hub、Cloudflare、第三方解析或遥测服务。
- 代理转发只处理由目标 WeChat 进程发起的网络请求；任何非转发性质的第三方外联都视为安全失败。

## 11. 错误处理

### 11.1 安全前置失败

任何安全边界不满足时立即停止，不自动降级到上游默认行为。

### 11.2 人工处理状态

登录、扫码、真人验证和目标页面上下文问题进入显式等待状态，不计入自动重试次数。每个等待事件默认限时 300 秒；操作员可在超时前通过显式操作延长一次，延长时长固定为 300 秒。系统不得自动延长，也不得对同一等待事件延长第二次。

首次 300 秒或延长期到期后，系统必须停止发出新的微信请求，原子保存不含秘密的检查点，并立即执行第 15 节清理。若尚未检查点保存任何有效作品，`job.status` 记为 `requires_human`；若已保存至少一个有效作品或评论记录，`job.status` 记为 `partial`。操作员主动取消按相同规则处理。

### 11.3 短暂故障

网络超时或连接中断最多自动重试两次。第一次重试前等待 2 秒，第二次重试前等待 5 秒，且仍需满足相邻微信 API 请求至少间隔 1 秒。

遇到微信限流或访问拒绝时停止自动请求并进入人工可见的等待或失败状态。不得提高频率、轮换账号或以其他方式规避限制。

### 11.4 单作品失败

单作品失败时保存脱敏证据和错误类别，然后继续后续作品。`job.status` 记为 `partial`；`capability_status` 和 `coverage_status` 按第 14 节独立判断，不能用能力或搜索覆盖结论掩盖运行未完整完成。

### 11.5 结构漂移

无法识别的新响应结构必须保留原始响应 SHA-256、字段名、类型、数量和脱敏扫描结果，标记 `schema_drift`，停止受影响的映射。只有满足第 8 节的显式批准、扫描、加密和立即删除要求时，才能临时保留加密原始证据；不得通过猜测字段含义继续生成看似有效的结果。

## 12. 测试策略

### 12.1 单元测试

覆盖：

- 搜索响应的已知嵌套结构变体。
- 原始顺序、跨页排名和作品 ID 去重。
- 已验证结束字段触发搜索耗尽；空页、缺失游标或本地超时不得误判为耗尽。
- 不同作品媒体类型的映射。
- 一级评论和二级回复分页。
- 内嵌回复与独立回复分页合并。
- 100 条一级评论和 200 条回复上限。
- 评论 ID 去重和父子关系语义。
- 缺失字段与 `null` 输出。
- `missing_in_source`、`redacted_for_safety` 与其他字段验证状态不混淆。
- 时间和媒体类型格式化。
- 原子写入、检查点和中断恢复。
- 日志脱敏和敏感字段拒绝。
- URL 查询参数和片段剥离，以及普通输出写入前的秘密扫描。
- `job.status`、`capability_status` 和 `coverage_status` 的独立判定。

### 12.2 模拟集成测试

使用模拟微信页面 WebSocket 客户端验证：

- 能力握手和只读方法白名单。
- 搜索、详情、评论请求的端到端编排。
- 搜索取得 10 个作品与搜索明确耗尽不足 10 个作品两种覆盖路径。
- 登录等待和页面上下文等待状态、300 秒超时、单次 300 秒延长和禁止二次延长。
- 人工等待超时后保存检查点、停止请求、进入清理并正确区分 `requires_human` 与 `partial`。
- 超时、重试、限流、单作品失败和结构漂移。
- 内存原始响应哈希、脱敏证据摘要和规范化证据引用。
- 未经扫描的原始响应不会落盘，临时加密原始证据不会产生明文文件且能在清理时删除。

### 12.3 安全测试

- 源码和构建产物中不得出现静态 RSA 私钥。
- 最小注入包中不得出现微信写操作方法或 POC 禁止路由。
- 启动前后 Windows 动态端口范围保持不变。
- 所有 POC 监听地址均为回环地址。
- POC 不生成硬件指纹文件。
- POC 不连接上游云 Hub、GitHub 更新、指标、Cloudflare 或第三方解析服务。
- 未携带正确本地令牌的请求被拒绝。
- 日志、普通结果和脱敏证据中不存在 Cookie、Authorization、令牌、带敏感查询参数的 URL 或私钥。

### 12.4 构建来源验证

- 从审核后的源代码编译，不执行仓库提交的 exe。
- 记录基线提交、工作树差异摘要、Go 版本、模块校验结果和构建产物 SHA-256。
- 在真实运行前执行 `go mod verify`、测试套件和构建产物安全扫描。

## 13. 真实验证环境

- 使用可回滚或可销毁的隔离 Windows 虚拟机。
- 在该虚拟机内重新登录 PC 微信并由人工完成任何登录或真人验证；不得复制宿主机微信登录数据。
- 确认视频号可访问后、安装 POC CA 或加载驱动前创建登录基线快照；后续运行可恢复并复用该快照中的登录状态。
- 宿主机不安装 POC CA、SunnyNet 驱动或代理设置。
- 运行前记录证书库、驱动、监听端口和动态端口范围基线。
- 运行后比较差异并执行清理。
- 真实评论正文、账号、令牌和其他敏感结果不进入 Git、聊天或非受控日志。

## 14. 验收结论

验收必须同时报告运行、能力和搜索覆盖三个维度。三个维度不得合并成单一的 `passed`/`failed`，也不得用搜索样本数量替代技术能力判断。

### 14.1 运行状态 `job.status`

- `completed`：搜索自然结束，并且所有入选作品均采集到接口结束或已确认上限，随后完成清理。
- `requires_human`：人工等待到期或被取消，且尚未检查点保存任何有效作品。
- `partial`：已保存至少一个有效作品或评论记录，但人工等待到期、被取消，或一个以上入选作品未采集到接口结束或上限。
- `failed`：核心接口不可用、响应无法安全解析、清理无法完成，或者发生任一安全边界违规。

### 14.2 能力状态 `capability_status`

#### `verified`

必须同时满足：

- `job.status` 为 `completed`。
- 已处理前 10 个有效作品，或在搜索明确耗尽时处理了全部有效作品；作品数量不足 10 不影响本项判断。
- 样本中实际观察到至少一条一级评论和一条二级回复。
- 作品 ID、作品排名和已返回的评论 ID 均已保存，并可关联到脱敏证据摘要、响应内序号和原始响应 SHA-256。
- 待验证字段类别均至少在一个适用样本中由微信源响应明确返回并完成映射：评论 ID、二级回复父评论 ID、正文或非文本内容类型、公开账号、时间、IP 属地、作品媒体类型和作品定位字段。
- 所有安全测试通过且清理成功。

#### `verified_with_gaps`

除“所有待验证字段类别均被实际观察到”之外，必须满足 `verified` 的全部采集、安全和清理条件。一个或多个待验证源字段在整个样本中始终缺失时使用该状态，例如 IP 属地或显式父评论 ID。缺失项必须明确报告为 `missing_in_source`，且不能存在结构解析错误。

#### `inconclusive`

采集没有发生安全失败，但样本或运行过程不足以验证完整评论链路，包括但不限于：

- 所有入选作品均没有公开一级评论。
- 样本中没有任何二级回复，无法验证回复能力。
- `job.status` 为 `requires_human` 或 `partial`。

搜索明确耗尽且不足 10 个作品本身不属于 `inconclusive` 条件。

#### `failed`

核心搜索或评论接口被可靠证据证明不可用、响应无法安全解析、清理失败，或者发生任一安全边界违规。

`verified_with_gaps` 只适用于源字段缺失，不能用于掩盖采集未完成、结构解析错误或安全失败。

### 14.3 搜索覆盖状态 `coverage_status`

- `target_met`：按原始顺序取得 10 个带有效作品 ID 的公开作品。
- `source_exhausted_below_target`：微信接口明确报告搜索耗尽，取得少于 10 个有效作品，并已保留全部有效作品。
- `incomplete`：既未取得 10 个有效作品，也未能确认搜索耗尽，例如搜索超时、错误或被人工取消。

`source_exhausted_below_target` 反映品牌样本量，不表示采集器不可行。三个维度分别输出各自的原因码；除安全或清理失败同时强制 `job.status=failed` 和 `capability_status=failed` 外，不设置跨维度状态优先级。

## 15. 清理与保留

清理必须幂等，并只操作本次任务记录的精确目标：

1. 停止采集器、代理、HTTP 和 WebSocket 服务。
2. 移除本次任务的 `WeChatAppEx.exe` 驱动规则。
3. 尝试注销本次测试驱动和删除其临时文件。
4. 按本次任务记录的 SHA-256 指纹移除 CA，禁止按 `Sunny` 或 `SunnyNet` 名称模糊删除。
5. 立即删除任何临时加密原始证据及其密钥、CA 私钥、会话令牌和临时配置。
6. 验证没有 POC 进程、非预期监听、测试证书或活动驱动规则残留。
7. 输出不含敏感数据的 `cleanup-receipt.json`；只记录删除类别、数量和成功状态，不记录密钥、原始响应或敏感文件名。
8. 将获准保留的结果复制到受控且被 Git 忽略的位置。
9. 回滚到“登录完成、POC 系统变更前”的基线快照，或销毁隔离虚拟机。

如果驱动或系统文件无法在运行中的虚拟机内完全移除，则清理状态保持未完成，直到虚拟机回滚到运行前快照或被销毁。只有系统基线已恢复，或虚拟机已销毁，清理才能记为成功。

临时加密原始证据及其密钥、CA 私钥和临时令牌在验收完成、任务终止或超时清理时立即销毁。只有规范化结果、脱敏证据、验证报告、清单、清理回执和运行日志可以最多保留 7 天；到期后由清理命令删除。销毁虚拟机是登录状态、驱动、证书和临时系统变更的最终回收保障。

## 16. 后续阶段边界

本规格获批并写入仓库后，下一阶段才编写实施计划。实施计划完成并再次确认后，才能修改代码、编译 POC 或执行真实验证。

TrendRadar 接入必须等待本 POC 得出 `capability_status=verified` 或 `capability_status=verified_with_gaps` 结论，并另行设计统一作品和评论模型映射。
